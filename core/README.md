# Core module

`core` contains the desktop domain logic under `src/desktopMain/kotlin/app/resound`. The desktop target is JVM and shares the domain contracts with the existing Android application where the platform boundary allows it.

## Desktop adaptations and explicit limits

- **Network ASR:** Doubao and OpenAI-compatible providers run through the desktop HTTP client. The desktop UI copies supported audio files into app cache and creates a durable import queue row; upload starts only after the user clicks the cloud transcription action. Local Android ASR is deliberately unavailable: Android service, NPU/QNN, model installer and sherpa-onnx runtime assumptions are not present on desktop. `LocalAsrProvider` returns `AsrError.ModelMissing` with `桌面版暂不支持`; it does not report a successful empty transcript.
- **Audio decode/export:** Android `MediaCodec` was replaced by FFmpeg subprocess adapters; WAV duration is read from RIFF metadata and raw PCM uses the documented 16 kHz mono s16le convention. Canonical 16 kHz mono PCM/WAV can be read for voiceprint inference without FFmpeg; compressed imports need `ffprobe` for duration, and compressed ASR/voiceprint inputs are normalized to PCM16/16 kHz/mono by FFmpeg. FFmpeg and ffprobe must be installed and available on `PATH` for compressed formats; missing tools or unsupported/corrupt audio are explicit errors. The UI has explicit start/stop desktop microphone recording and voice-sample enrollment actions. Manual capture writes local PCM into the durable ASR queue; upload remains a separate user action.
- **Background work:** WorkManager workers were adapted to the platform scheduler. Desktop jobs do not inherit Android battery, foreground-service or notification-permission semantics; startup recovery is owned by the desktop scheduler and app lifecycle.
- **Search and voiceprint:** Keyword search is available through FTS; semantic search is opt-in: the user must click the enable button before the scheduler downloads the pinned, SHA-256-verified BGE model (~24 MB) and indexes events/items locally (transcript lines are not vector-indexed). Once ready, results are merged with keyword hits via RRF; if the model is missing or inference fails, search falls back to keywords with a visible status. The licensed CAM++ ONNX model is bundled with the desktop app, copied to the user data directory on first enrollment and checked against its pinned SHA-256. User-triggered recording adds a local “我” voice sample and schedules local matching over retained transcripts; at least three trusted samples totaling 30 seconds are required for readiness. Android `Context`, `AtomicFile`, and `AudioRecord` paths were removed. Speaker diarization remains explicitly unsupported because the required desktop native sherpa-onnx runtime is not packaged; the desktop implementation throws `UnsupportedOperationException` instead of inventing speaker labels. Microphone and ONNX inference need validation on a real desktop.
- **Digest and topics:** Ordinary text digestion and `TopicKind.Normal` produce persisted memory events through the Room KMP database. Android `withTransaction` calls use the desktop `inTransaction` adapter. Specialized topic types that depend on Android skill/import pipelines fail explicitly with `UnsupportedOperationException`.
- **Digest thing extraction:** The optional Android `DigestThingExtraction` revision workflow is not wired into the desktop digest path. Desktop digest persists ordinary events and items without claiming that optional extraction ran.
- **Ask/diary/reviews:** The desktop Ask entry is a one-shot, read-only retrieval answer: local FTS and any opt-in event/item vectors supply up to eight excerpts, then only an explicit user action sends those excerpts and the question to the configured LLM. Returned citation numbers are restricted to retrieved sources. It does not persist conversations, call mutation tools, or provide Android place/thing tools. Markdown diary export reads local events, items, transcript lines, and stored daily reviews. The desktop `ReviewRepository` adapter is read-only: it does not generate reviews, schedule notifications, or sync diary files to cloud storage; unsupported review settings report an explicit error.
- **Secrets and preferences:** Android SharedPreferences/Keystore adapters were replaced with the desktop `KeyValueStore` and platform secret store. The UI and app graph must use these injected desktop adapters.
- **Android interaction points:** Android backup/restore document pickers, runtime notification permission, exact alarms, and foreground services do not exist on desktop. File operations use desktop paths and OS notifications are best effort. Exact alarm scheduling is reported unavailable.

## Verification

Run `cmd.exe /c "gradlew.bat :core:compileKotlinDesktop --console=plain --continue"` from the repository root. Native installers are built on their target operating system: MSI on Windows, DMG on macOS, and DEB on Linux.
