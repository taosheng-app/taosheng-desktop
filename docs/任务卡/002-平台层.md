# 任务卡 002：平台层（波次 1）

## 目标

把后面所有业务代码要用、但安卓与桌面实现不同的系统能力，抽成 `platform` 模块里的**端口接口 + 桌面实现**，让波次 2～5 的业务迁移时只需把 `Context`/`SharedPreferences`/`WorkManager`/`Keystore`/`NotificationManager` 等换成这里的接口，不再碰系统 API。

总计划见根目录 `plan.md`；上一张卡见 `docs/任务卡/001-交付说明.md`。安卓原项目在 `D:\projects\github\TaoSheng`（只读）。

## 调研结论（决定接口形状）

- **SharedPreferences**：40 个命名文件，调用 `getString` 425 次、`getLong` 163 次、`getBoolean` 107 次、`getInt` 70 次，`edit()` 176 次（`commit()` 119、`apply()` 57）、`remove` 149、`contains` 76，另有 `putStringSet`、`registerOnSharedPreferenceChangeListener`（5 处）。→ 做一个**接口与 `SharedPreferences` 一一对应**的 `KeyValueStore`，业务代码几乎只需改类型名和 `getSharedPreferences(...)` 的来源。
- **SecretStore**（安卓 `digest/SecretStore.kt`）：`read/write/remove/has`，AES-GCM，12 字节 IV 前置，写失败抛“密钥保存失败，请重试”。→ 同样的四个方法，桌面用系统钥匙串保护主密钥。
- **WorkManager**：49 个文件、30 个 Worker。用到的能力：唯一任务（`KEEP/REPLACE/APPEND_OR_REPLACE`）、周期任务（`KEEP/UPDATE`）、初始延迟、指数退避、`NetworkType.CONNECTED/UNMETERED` 约束、输入数据、标签、取消、查询状态（`ENQUEUED/RUNNING/BLOCKED/FAILED`）、`Result.success/failure/retry`。→ 做**进程内调度器 + 持久化任务表**，API 形状贴近 WorkManager。
- **通知**：19 个文件、8 个渠道，用到标题/正文/深链/重要级/点击打开/自动取消、紧急提醒。→ `Notifier` 端口；桌面用系统托盘气泡，深链点击回到主窗口。
- **文件路径**：`filesDir` / `cacheDir` / `noBackupFilesDir`（82 处）。→ `AppDirs`。

## 约定

- 接口放 `platform/commonMain`（不含 `java.*` 之外的平台类型也可，但 `File` 先用 `java.io.File`，接口放 `desktopMain` 可以；**原则：接口与实现同放在 `desktopMain`，除非是纯中立类型**，与 plan 的“业务代码放 desktopMain”一致）。
- 不引入 DI 框架；各实现在 `desktopApp` 里装配（本卡只提供实现和一个 `DesktopPlatform` 工厂）。
- 所有会落盘的东西统一放在 `AppDirs.data`（见下），不散落到用户目录别处。
- 线程安全：`KeyValueStore`、`SecretStore`、调度器的公开方法都要可并发调用。

## 要做的

### 1. `AppDirs`

- `data`（持久数据，对应 `filesDir`/`noBackupFilesDir`）、`cache`（可丢弃，对应 `cacheDir`）、`logs`。
- 默认位置：Windows `%APPDATA%\Taosheng`；macOS `~/Library/Application Support/Taosheng`；Linux `$XDG_DATA_HOME/taosheng`（默认 `~/.local/share/taosheng`）。缓存分别用 `%LOCALAPPDATA%\Taosheng\Cache`、`~/Library/Caches/Taosheng`、`$XDG_CACHE_HOME/taosheng`。
- 系统属性 `resound.home` 可整体覆盖（测试与便携模式用）；目录不存在时创建。

### 2. `KeyValueStore`（对应 `SharedPreferences`）

- 接口：`getString/getInt/getLong/getBoolean/getFloat/getStringSet`（带默认值）、`contains`、`all`、`edit()` 返回 `Editor`（`putX`、`remove`、`clear`、`commit(): Boolean`、`apply()`）、`addListener/removeListener`（键变化回调）。
- 实现：每个命名库一个 JSON 文件（`data/prefs/<name>.json`），**原子写**（临时文件 + 改名），损坏文件备份为 `.corrupt` 后按空库启动；内存缓存 + 写穿；`commit()` 同步落盘，`apply()` 异步合并落盘。
- 工厂 `KeyValueStores.get(name)`：同名返回同一实例。
- 类型严格：同一键先存 `String` 后按 `Int` 读，返回默认值而不是抛错（与 SharedPreferences 的 `ClassCastException` 相比更稳，需在文档里写明差异）。

### 3. `SecretStore`

- 与安卓同名同签名：`read(name): String`（不存在返回 `""`）、`write(name, value)`、`remove(name)`、`has(name)`。构造参数 `(store: KeyValueStore, alias: String, keyProvider: MasterKeyProvider)`。
- 加密：AES-256-GCM，12 字节随机 IV 前置，Base64 存入 `KeyValueStore`（与安卓格式一致，便于以后做备份互通）。
- `MasterKeyProvider` 端口：`getOrCreate(alias): ByteArray`。桌面实现优先 **系统钥匙串**（Windows 凭据管理器 / macOS 钥匙串 / Linux Secret Service，用 java-keyring）；不可用时回退到 `AppDirs.data` 下受文件权限保护（仅当前用户可读）的主密钥文件，并在日志里**只写一次**“已回退到文件密钥”，界面以后可提示。
- 任何日志、异常信息不得出现明文或密钥；写失败抛 `IllegalStateException("密钥保存失败，请重试")`。

### 4. `Scheduler`（对应 WorkManager）

- API：`enqueueUnique(name, request, policy)`、`enqueuePeriodic(name, request, policy)`、`cancel(name)`、`cancelByTag(tag)`、`status(name)`、`observe(name): Flow<List<TaskInfo>>`。
- `TaskRequest`：`worker`（已注册的任务类型 id）、`input: Map<String, Any?>`（Int/Long/Boolean/String）、`initialDelay`、`constraints`（`requiresNetwork: None/Any/Unmetered`）、`backoff`（线性/指数、起始时长，默认指数 30 秒，上限 5 小时，同 WorkManager）、`tags`、`expedited`（本机不区分，只影响优先级）。
- 策略：`Keep`（已有同名未完成任务则忽略）、`Replace`（取消旧的再入队）、`AppendOrReplace`（排在旧任务之后，旧任务失败则替换）；周期任务 `Keep`/`Update`，最小间隔 15 分钟（同 WorkManager）。
- `TaskResult`：`Success`、`Failure`、`Retry`；`Retry` 按退避重新排队，累计尝试次数。
- **持久化**：任务表落盘（`data/scheduler.json`），进程重启后恢复未完成任务，到期的立即补跑；**停机期间错过的周期任务只补跑一次**。
- 并发：全局最大并发数可配（默认 4）；同名任务不并发；网络约束通过 `NetworkMonitor` 端口判断（实现：尝试解析/连接检测 + 系统属性开关，`Unmetered` 在桌面无法可靠判断，**统一按“有网络即视为不计流量”处理并在文档里写明**）。
- Worker 注册：`registerWorker(id) { input, context -> TaskResult }`，`context` 里有 `isCancelled` 与 `progress`。

### 5. `Notifier`

- 端口：`send(channel, title, body, deepLink?, importance)`、`cancel(id)`、`isPermitted(channel)`。
- 渠道 `NotificationChannelSpec(id, name, importance)`，沿用安卓 8 个渠道的 id 与中文名常量（`listening`、`interrupted`、`import`、`daily-review`、`skill-generation`、`todo-reminder-2`、`llm-balance`、`transcribe` 等）。
- 桌面实现：`java.awt.SystemTray` 气泡；系统不支持托盘时（部分 Linux）回退为应用内通知队列（`Flow<NotificationEvent>`，由界面层展示）。点击通知触发 `onActivate(deepLink)` 回调。`High` 重要级的通知额外置顶提示（具体弹窗留给界面卡）。
- 测试用 `RecordingNotifier`。

### 6. `Clock` 与 `NetworkMonitor`

- `Clock`：`now()`、`elapsedRealtime()`（单调），供测试替换。安卓代码里 `SystemClock.elapsedRealtime` 28 处统一走它。
- `NetworkMonitor`：`isOnline(): Boolean`、`observe(): Flow<Boolean>`。

## 测试

- 每块 2～4 个用例，覆盖“正常一条 + 最可能出错的一两条”：
  - `KeyValueStore`：读写与类型、原子写后重开、损坏文件降级、监听器触发、并发写不丢。
  - `SecretStore`：往返、密文不含明文、篡改密文读取失败的处理、`remove/has`。
  - `Scheduler`：唯一任务 `Keep/Replace`、`Retry` 退避与次数、周期任务、重启恢复（用临时目录建两个实例模拟）、取消。
  - `AppDirs`：`resound.home` 覆盖与三种系统路径计算（路径计算写成纯函数，用参数模拟三平台）。
  - `Notifier`：渠道与记录；无托盘时回退。
- 时间相关测试用可注入的 `Clock`，**不要 `Thread.sleep` 等真实时间**。
- 能通过 `.\gradlew.bat build`。

## 不做

具体业务任务（转写、备份等）的迁移；开机自启与托盘菜单（波次 7）；前台服务语义；定位与蓝牙。
