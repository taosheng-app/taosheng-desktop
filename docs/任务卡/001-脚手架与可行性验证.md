# 任务卡 001：桌面版脚手架与可行性验证

## 目标

把当前的单模块 Hello World 拆成 4 个模块，并用 4 个最小验证确认迁移方案走得通。**这是整个迁移的门槛：任一项验证不通过，先停下来给负责人看结论和替代方案，不继续往后做。**

总计划见根目录 `plan.md`，**必须先读**。安卓原项目在 `D:\projects\github\TaoSheng`（只读，不要修改）。

## 约定

- 包名保持 `app.resound.*`（业务代码），入口等桌面外壳用 `app.resound.desktop`。
- 依赖方向 `desktopApp → ui → core → platform`，不得反向。
- 目标统一为 `jvm("desktop")`；业务代码放 `desktopMain`，只有真正中立的接口放 `commonMain`。
- 现有 `composeApp` 的内容迁移到 `desktopApp`/`ui`，不留空壳。
- 不要修改安卓仓库；从中拷贝代码时保留 MIT 版权声明（在仓库 `LICENSE` 或 `NOTICE` 里写明来源）。

## 要做的

### 1. 模块拆分

- `platform/`、`core/`、`ui/`、`desktopApp/` 四个模块，`settings.gradle.kts` 与 `gradle/libs.versions.toml` 同步更新。
- `desktopApp` 仍然能 `.\gradlew.bat :desktopApp:run` 弹出现有的 Hello World 窗口；`composeApp` 删除。
- 版本目录里补齐：Room KMP、KSP、sqlite-bundled、onnxruntime、kotlinx-coroutines、OkHttp、org.json、JUnit。

### 2. 验证 A：Room KMP + FTS4 + 裸 SQL（最关键）

- 在 `core` 里用 Room KMP + `BundledSQLiteDriver` 建一个最小库，从安卓 `data/CaptureDatabase.kt` 与 `search/` 里**原样搬**：`SegmentEntity`、`TranscriptLineEntity`、一个 `@Fts4` 实体（`lines_fts`）及其触发器、一条 `MATCH` 查询、一条 `openHelper` 式裸 SQL 的替代写法。
- 验证点：KSP 能生成代码；FTS4 建表、触发器、中文分词查询可用；事务封装（对应安卓 `withTransaction`）可用；Flow 查询可用。
- 若 FTS4 不可用，给出备选（手写 SQL + `SQLiteConnection`）并实测一次。

### 3. 验证 B：ONNX Runtime（JVM）

- 加载安卓 assets 里的 `silero_vad.onnx`（只读拷贝一份到测试资源），喂一段 16k PCM，得到语音概率。
- 对照安卓 `audio/SileroVad.kt` 的输入输出形状，确认结果合理（静音低、人声高）。

### 4. 验证 C：麦克风采集

- 用 `javax.sound.sampled` 开 16kHz/单声道/16bit 采集，按 30 毫秒（480 采样）出帧，对接 `AudioSource` 接口（从安卓 `audio/AudioSource.kt` 原样搬，签名不改）。
- Windows 上实测：能录、能取消、设备被占用或没有麦克风时给出 `AudioSourceException` 而不是崩溃。
- macOS/Linux 没有环境，只在交付说明里写明待测项和已知权限要求。

### 5. 验证 D：ffmpeg 编解码

- 用 ffmpeg 子进程把 16k PCM 编成 OGG/Opus 和 M4A/AAC，再解回 PCM，对照时长与采样数。
- 弄清并写进交付说明：ffmpeg 来源与许可证（要求 LGPL、不含 GPL 组件）、体积、随安装包分发的方式、找不到 ffmpeg 时的报错。

## 测试

- 每项验证 1～3 个单元测试（正常一条 + 最可能出错的一条）；麦克风验证写成可跳过的测试（无设备时跳过）。
- 能通过 `.\gradlew.bat build`。

## 不做

迁移任何业务代码（`capture`、`transcribe`、`digest` 等）、完整数据库、界面、托盘、打包发布。
