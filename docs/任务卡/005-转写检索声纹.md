# 任务卡 005：转写、检索与声纹模块迁移

## 目标与范围

将 Android 的 `transcribe`、`search`、`voiceprint` 业务层迁移至桌面 `core`，通过平台接口提供操作系统能力。

- 转写支持 Doubao 与 OpenAI 兼容接口；本地 Android ASR/NPU 暂不支持。
- 检索使用 desktop app directories 与 platform scheduler；模型计算仍由可注入的模型接口提供。
- 声纹仓库、特征缓存与麦克风接入改用桌面文件和音频边界。

## 桌面适配

- `:core:compileKotlinDesktop` 已通过。
- HTTP/密钥、设置、调度器、模型目录、音频采集均采用注入的 desktop adapter，不在业务层读取 Android `Context`。
- MediaCodec 解码与导出改为 FFmpeg 子进程；缺少 FFmpeg 时返回明确错误。
- Android WorkManager 改为 platform scheduler。
- 本地 ASR 保持 `AsrError.ModelMissing`，详情为“桌面版暂不支持”；不返回伪造的空转写。
- 说话人分离因桌面 sherpa-onnx native runtime 未打包而显式不支持，不生成虚假 speaker labels。
- Android NPU/QNN、原生 VAD 及设备省电/前台服务策略未移植；桌面不继承 Android 电量和通知权限假设。

## 验收状态

1. **核心编译：通过。** 命令：`cmd.exe /c "gradlew.bat :core:compileKotlinDesktop --console=plain --continue"`。
2. **桌面入口：部分完成。** 桌面 AppGraph 接入了大模型设置、手动文本 Digest、基于 FTS 的本地转写/事件/事项关键词搜索，以及文件导入→持久队列→用户点击启动的 Doubao/自定义云端 ASR。导入会复制到应用缓存；WAV 时长从 RIFF 元数据读取，原始 PCM 按 16 kHz 单声道 s16le 计算，压缩音频时长依赖 ffprobe，压缩音频 ASR 依赖 FFmpeg 解码。发送音频前需用户点击“开始云端转写”，可能产生服务费用；转写结果进入数据库，只有再点击“整理识别结果”才发给大模型。麦克风入口可显式开始/停止录音并把 PCM 留在本机、加入持久转写队列，只有用户点击云端转写才上传；另有最长 15 秒“我”的声纹样本录制入口。随包提供 Apache-2.0 CAM++ 模型并在首次录入时校验 SHA-256，然后本地对已有转写重算身份；至少 3 条、累计 30 秒才标为就绪。仅支持身份匹配，不提供说话人分离。语义搜索：搜索框上方提供“启用语义搜索”按钮，用户点击后才会通过 platform scheduler 下载固定版本、带 SHA-256 校验的 BGE 小型中文 ONNX 模型（约 24 MB）并在后台为事件/事项建立本机向量索引；就绪后搜索将关键词结果与余弦相似度结果做 RRF 合并，未就绪或推理失败时退回关键词搜索并在界面显示状态。转写句不建向量索引。麦克风/本机模型推理、语义模型下载和实际云端服务请求、格式兼容、费用尚未端到端验证。
3. **Android 独有逻辑：已记录在本卡与 `core/README.md`。**
