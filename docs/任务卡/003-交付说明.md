# 任务卡 003 交付说明

日期：2026-11-13。

## 做了什么

1.  **数据层迁移**：搬迁 `app/src/main/java/app/resound/data/*` 等 20 个文件，包含全部 39 个实体、19 个 DAO。
    -   表结构与安卓 **v33** 完全一致（字节对比通过）。
    -   所有 32 个迁移（`MIGRATION_1_2` ... `MIGRATION_32_33`）保持原有 SQL 逻辑，全部适配为 `SQLiteConnection` 实现。
    -   `RawQuery`：被固定查询 `SELECT ...` 取代，通过同时引用三张表观察失效，**已通过 Mutation 测试（破坏观察条件即失败）**。
    -   `@Transaction`：保持。所有 `db.withTransaction` → `db.inTransaction`（内部用 `immediateTransaction`）。
2.  **基础包迁移**：`usage`, `prompts`, `privacy`, `diagnostics`, `onboarding`, `context` 已搬，Android API（如 `Context`）已剥离，依赖注入。
3.  **兼容性验证**：已实现 `CaptureDatabaseMigrationTest`，自动测试从安卓 v1 到 v33 的全部迁移路径，保证生产环境迁移与安卓一致。

## 差异对照

| 区域 | 改动 |
|---|---|
| `*Schema.kt` | `SupportSQLiteDatabase` → `SQLiteConnection`；`execSQL` → `exec` |
| `ReviewDao.kt` | `@RawQuery` → `@Query`（同时引用 `memory_events`, `memory_items`, `embeddings`） |
| DAO 事务 | `db.withTransaction` → `db.inTransaction` |
| 外部包 | `Context` 参数 → 剥离（改为通过 `DesktopPlatform` 注入的 `dirs`） |

## 遗留与限制

-   `RawQuery` 改动：理论上查询复杂度增加（引用三张表），但实际只是 `SELECT 1` 计数，开销极低。
-   小型包的 Android API 移除：在 `prompts` 中，原先从 assets 读，现改为 classpath 资源；在 `diagnostics` 中，崩溃日志写入 `AppDirs.logs`。
