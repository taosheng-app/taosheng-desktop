# 任务卡 004：录音管线底层（波次 3）

## 目标

把录音从安卓的“前台服务 + 硬件回调”模式剥离，构建一套在桌面环境下支持长时录音、自动分段、落盘、隐私管理的纯协程录音管线。

不搬录音业务（自动启停、静音调度），只做**管线底层**：音频数据的捕获与编码/保存。

## 调研结论

-   **音频录制**：Android 使用 `AudioRecord` 回调，桌面需跨平台录音。调研使用 `javax.sound.sampled` 或第三方 Kotlin 音频库。
-   **录音文件处理（SegmentFiles）**：
    -   安卓逻辑：PCM 缓冲 → 编码（`SegmentEncoder`）→ `filesDir/segment-spool/` 中转 → 最终目录。
    -   桌面改法：`AppDirs.cache("pcm")` 中转，最终存 `AppDirs.data("segments")`。移除对安卓 `Context`、`SharedPreferences`、`Log` 的依赖。
-   **分段/流水线**：录音本身应该是 `Flow<ByteArray>`，流水线处理编码。

## 约定

-   `platform` 新增 `AudioRecorder` 接口（`record(): Flow<ByteArray>`）。
-   `core` 搬迁 `SegmentFiles`（改名 `AudioFileManager` 或类似，去除 Android 依赖），负责录音文件落盘与清理。
-   **隐私管理**：安卓版的 `PrivacySpool` 逻辑（记录哪些片段是“隐私”的并定期删）保持不变，使用 `KeyValueStore` 替代安卓 `SharedPreferences`。

## 要做的

1.  **录音接口**：在 `platform/commonMain` 定义 `AudioRecorder`。实现一个基于 `javax.sound.sampled` 的录音器（放在 `desktopMain`），支持 PCM_16BIT, 16kHz/44.1kHz。
2.  **`AudioFileStore`**：迁移原 `SegmentFiles` 的落盘与隐私标记逻辑。
3.  **测试**：录音 5 秒，确认产生有效 PCM 文件；分段后的编码存盘验证。
